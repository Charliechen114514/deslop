# 机制：自检（checks/）

词形问题交给脚本，压缩病交给干净上下文的子代理，配方改动的底线交给回归集，装前冲突交给提示词。你手里的自检各管一段，都住在 checks/ 里。

## lint.py：词形判罚引擎

引擎只认两种数据，都写在 markdown 里，你加规则不用碰代码：

1. **词表**：任何带"禁 | 改成"表头的表格，一行一条规则。第三列可以写具名条件，引擎认得"仅当标签"和"除非真实顺序"，认不得的条件名自动降回语义层并告警。写了语义条件的行（比如"当标签用"）不进机械层，那是模型的活，不是正则的活。
2. **lint 块**：层文件里标记为 lint 的围栏块，一行一条"正则 ## 备注 ## 级别"。级别两级：error，命中即罚。review，只是候选，语义说了算。

你装了哪些层，它就查哪些层：引擎读 build/combo.json（经 tools/bake 解析）拿当前组合，所以第三方层自带的 lint 块也自动生效，零代码改动。md 是正本，脚本是执行器。组合怎么编译出来的，看 [how-it-works.md][how-it-works]。

还有一条计数不来自 markdown，硬编码在引擎里，你不用配：全文数一遍"——"，超过一处，报 review 级"破折号超限"（recipes/flaws/anti-ai.md 第 10 条的限额）。这个计数连代码围栏里的内容一起数，下面说的围栏跳过只罩词表和 lint 正则。重锚机制里有个回合收尾的钩子 gate.py，叫拦截器，机制见 [anchoring.md][anchoring]。它机械计数里的"破折号限额"查的就是这条。

你引用原话、讨论禁词本身，是正当用途，所以「」、弯引号、直引号、反引号包住的内容不查词表。这个豁免只罩词表，lint 块的正则照查原文，error、review 级都查。代码围栏整段跳过。

跑法：

```bash
python3 checks/lint.py 某文件.md                     # 查一个文件
cat 某文件.md | python3 checks/lint.py               # 管道输入
python3 checks/lint.py --layers a.md,b.md 某文件.md  # 临时指定层，绕过当前组合
python3 checks/lint.py --self-test                   # 引擎自测
python3 checks/lint.py --report                      # 列出当前组合的全部规则
```

退出码：0 干净或只剩 review，2 有 error 命中，3 自测失败。

引擎只管词形。句式骨架类的问题（比如平衡句骨架）、情绪预设类的问题（比如替对方发明他没说过的感受）、翻译腔的语义病（英文句法直译进中文的句子），这三类正则查不出来，你只能靠模型按配方条款逐条走查，脚本不装懂。

## expansion-review.md：展开病审查

一份提示词，不是脚本，查的病有两个名：标题里叫展开病，行文里多叫压缩病，一个东西。你审不出自己的这种病，稿子在你眼里自带心里那版注释，所以它配一个干净上下文的子代理跑，不配你自己。

审查跟周期走，两个条件谁先到谁触发：写完任何一份要留下的文件，必审，文件是永久工件，不能带病出厂。或者对话攒满 5 个回合没审，就审一批，5 是默认拍数。维护者（装配方的人，就是你自己）喊一声"审"，无论长短当场放，不占 5 拍周期的额度。

喂给子代理的办法：写成文件的，你给它路径让它自己读，发出去超过一段的回复，你直接贴原文给它。

它只查三种压缩病：

- 光杆判决：名词短语加判决词收尾，谁的范围、哪种用法、为什么没收进句子。
- 名词排队：三个以上名词短语并列顶一句话，谁是谁没有交代。
- 关系词省略：两件事有因果、条件、转折，句子只用逗号把两半摆在一起。

清单回来你当场改，每处三行：原句、病名、展开版。

边界：它查压缩，不查别的。词形归 lint.py，规则打架归 style-conflict.md，最终过目归维护者，也就是你自己。你可以驳回清单里的某条，驳回要写理由，驳回记录跟着案子进回归集。

## cases.md：回归集

bad case 登记处，每条三行：反例、期望、归属（哪层哪条该拦住它）。你改了配方之后过一遍这集，别把治好的病放回来。

吸收机制：案例是证据，不随组合出门。坏例不许注入进模型要读的文件，因为注入通道是把配方文件整份复述给模型的，病句标本要是跟着配方一起被复述，就等于一轮接一轮给模型上坏例课。教训要起作用，必须升进随组合出门的载体，案底里把这叫毕业：正面写法进配方条款，好的展开进 build/voice.md（你自己的那份）里攒展开样板的一节，example 起步模板不带这节。同一案例复发满两次，必须毕业并在案底标去向。复发而条款已存在，说明条款写弱了，你该重写条款，不是再记一笔案。

## style-conflict.md：装前冲突检查

装配方之前，你把宿主项目的规则文件和要装的配方一起交给任意 LLM，按提示词查六类冲突：

- 直接矛盾：一边要求 X，一边要求非 X。
- 禁词撞车：配方判死的词，宿主自己的文档里大量使用，装上后模型读宿主文档会被自己的规则绊住。
- 优先级不明：两边管同一件事，都没写谁赢。
- 场景重叠：两份配方的场景层管同一个场景，细则不一致。
- 层间重叠：两份配方声明管同一个维度。
- 层卡核对：层卡声明的互斥和让位，跟实际装的组合对一遍，声明互斥的两份同时在装、或让位关系成环，都算冲突。

输出冲突清单和"能不能直接装"的判断。裁决顺序写死：用户当场的话 > 宿主规则 > 配方。

你在宿主规则文件和配方有大改之后重跑一次，平时不用。它查规则打架，不查写得好不好。
