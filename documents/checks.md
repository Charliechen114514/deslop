# 机制：自检三件（checks/）

词形问题交给脚本，语义问题交给模型，装前冲突交给提示词。三件各管一段。

## lint.py：词形判罚引擎

只认两种数据，都写在 markdown 里：

1. **词表**：任何带"禁 | 改成"表头的表格，一行一条规则。第三列可以写具名条件，引擎认得"仅当标签"和"除非真实顺序"，认不得的条件名自动降回语义层并告警。写了语义条件的行（比如"当标签用"）不进机械层，那是模型的活，不是正则的活。
2. **lint 块**：层文件里标记为 lint 的围栏块，一行一条"正则 ## 备注 ## 级别"。级别两级：error，命中即罚。review，只是候选，语义说了算。

装哪层查哪层：引擎读 build/combo.json（经 tools/bake 解析）拿当前组合，所以第三方层自带的 lint 块也自动生效，零代码改动。md 是正本，脚本是执行器。

引用豁免：「」、弯引号、直引号、反引号包住的内容不查词表，讨论禁词本身、引用原话是正当用途（review 级的正则仍查）。代码围栏整段跳过。

跑法：

```bash
python3 checks/lint.py 某文件.md                     # 查一个文件
cat 某文件.md | python3 checks/lint.py               # 管道输入
python3 checks/lint.py --layers a.md,b.md 某文件.md  # 临时指定层，绕过当前组合
python3 checks/lint.py --self-test                   # 引擎自测
python3 checks/lint.py --report                      # 列出当前组合的全部规则
```

退出码：0 干净或只剩 review，2 有 error 命中，3 自测失败。

引擎只管词形。句式骨架类的问题（比如平衡句骨架）、情绪预设类的问题（比如替对方发明他没说过的感受）、翻译腔的语义病（英文句法直译进中文的句子），这三类正则查不出来，要靠模型按配方条款逐条走查，脚本不装懂。

## cases.md：回归集

bad case 登记处，每条三行：反例、期望、归属（哪层哪条该拦住它）。配方改动后过一遍这集，别把治好的病放回来。

吸收机制：案例是证据，不是疫苗，不随组合出门。坏例不许注入进模型要读的文件，因为注入通道是把配方文件整份复述给模型的，病句标本要是跟着配方一起被复述，就等于一轮接一轮给模型上坏例课。教训要起作用必须毕业，升进随组合出门的载体：正面写法进配方条款，好的展开进样板。同一案例复发满两次，必须毕业并在案底标去向。复发而条款已存在，说明条款写弱了，重写条款，不是再记一笔案。

## style-conflict.md：装前冲突检查

一份提示词，不是脚本。装配方之前，把宿主项目的规则文件和要装的配方一起交给任意 LLM，按提示词查六类冲突：直接矛盾（一边要求 X，一边要求非 X）、禁词撞车（配方判死的词，宿主自己的文档里大量使用，装上后模型读宿主文档会被自己的规则绊住）、优先级不明（两边管同一件事，都没写谁赢）、场景重叠（两份配方的场景层管同一个场景，细则不一致）、层间重叠（两份配方声明管同一个维度）、层卡核对（层卡声明的互斥和让位，跟实际装的组合对一遍，声明互斥的两份同时在装、或让位关系成环，都算冲突）。输出冲突清单和"能不能直接装"的判断。裁决顺序写死：用户当场的话 > 宿主规则 > 配方。

配方或宿主规则有大改之后重跑一次，平时不用。它查规则打架，不查写得好不好。
