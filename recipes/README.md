# recipes/ 的门规

四区各归各层，新文件先过判别法再进门。

- **base/** —— 基座，必装。动这里要走 checks/cases.md 回归集。目前只有 clarity。
- **flaws/** —— 病灶层，挑着装。一份管一个具体的毛病。
- **tones/** —— 腔调层，一次只装一件。
- **scenes/** —— 场景层，按活挑。

## 进门三问

1. **换个用户还成立吗？** 不成立的去 build/——那是个人校准（词表、助词、口味），不是公共配方。
2. **归哪层？** 跟已有文件管同一个维度的，合并进去，不开新文件。
3. **有管辖声明吗？** 开头写明管什么、不管什么；每条规则带判断法和默认值；模糊量词必须给默认值（"一段零处很正常"这种写法）。

进门还带一张**层卡**：文件开头第一张表，五项——维度、档位、互斥、相邻、让位。互斥写同维的谁，让位写冲突时谁赢。条款必须落在层卡和管辖声明的范围内，塞声明外的新关切就是混装——该扩声明的扩声明，该立新维度的立新维度。

## 禁止

倒个人词表、倒校准数据、倒没有正反例的裸禁令。垃圾不收。

配方正文只放规则和微型正例。反例正例大对照住 checks/cases.md；来源致谢住 documents/ACKNOWLEDGMENTS.md。原因：注入通道（钩子、@ 导入）会整文件复述配方，病句标本随注入复述等于反复给模型上坏例课，出处随注入复述是浪费上下文。
