# 病灶：翻译腔

| 层卡 | |
|------|------|
| 维度 | 病灶 |
| 档位 | 翻译腔 |
| 互斥 | 无同维互斥，与其他病灶正交（这边管中文纯度，那边管机器痕迹） |
| 相邻 | 行业术语、代码标识符不归本层 |
| 让位 | 正式术语当用的照用，判别法是白话能否无损替换 |

管辖声明：管句子像不像中国人自然说话。

翻译腔是英文句法直译进中文的痕迹。人和机器都会犯，AI 犯得更勤。

## 规则

1. 假冠词砍掉。"这一份指南""那一条路"是英文 this/the 的直译。直接说"这份指南""那条路"，或者干脆说"指南"。裸"这个、那个"放行，但必须指着前文真实出现过的东西。
2. 被动句少用。"配置被更新了"写"更新了配置"。被动只在真不知道谁干的、或者谁干的完全不重要时用。
3. "进行"拆掉。"进行了修改""对配置进行检查"写"改了""查配置"。"进行 + 双字名词"是公文腔，动作直接说。惯用搭配（进行手术、进行诉讼）放行，拆的是公文腔的"进行了一个 X"。
4. 长定语链剪短。"一个用来处理用户在登录时提交的数据的模块"——三个"的"串到底，读者到句尾已经忘了头。拆成两句，或者拆开说。
5. 普通词不夹英文。有自然中文就用：workaround 写"绕过方案"，edge case 写"边缘情况"。连语法位都不许杂交："不only看"写"不只看"，"很nice"写"很好"——中文的骨架配英文的词，比夹整个英文词更刺眼。代码标识符、行业专名不受限。
6. 动词掏空的，填回去。"扮演着衔接学员落差的角色""进行一个分切的动作""起到了缓冲的作用"——动作装在"角色、动作、作用"的盒子里，倒出来直接用动词：衔接、切、缓冲。判断法：删掉框子，动词留下，意思没变就删。一段零处很正常，出现即改。
7. "性/度"名词先问白话一句。"可读性高""稳定性好"是英文 -ability 的直译。白话有对等说法就用："好读""跑得稳"。行业里当正式术语用的放行（兼容性、灵敏度、可用性）。一段一两个正常，成串才改。
8. 介词框子拆掉。"关于 X 的问题""基于以上的考虑""有着重要的存在意义""由于 X 使得 Y"——先用介词搭架子再填话，是英文搬来的。直接说事。"作为"当"是"用的（"作为数据库，它……"）删掉；真表身份的（"作为监护人代签"）放行。公文标题的法定题式（"关于 XX 的通知"）照旧。一段零处正常。
9. 生造压缩语不许。概念有完整说法就写完整的："每五条来一次审查"不写成"五条一拍"，"四十七条测试全部通过"不写成"四十七测绿"。判断法：把缩略展开成完整句，如果读者需要重新解码才能懂，就写完整的。行业通用缩写（CI、API）不受限，受限的是自己临场发明的。
