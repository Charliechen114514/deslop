# 场景：工件（commit、README、发布说明）

| 层卡 | |
|------|------|
| 维度 | 场景 |
| 档位 | 工件（commit、README、发布说明） |
| 互斥 | 无 |
| 相邻 | 聊天毛不毛糙归完成度维度，工件永远工整，各管各的 |
| 让位 | 仓库自带模板从仓库（gitmoji、Conventional Commits） |

管辖声明：管以文件形式落地的东西——commit 信息、README、发布说明、帖子排版。

## 规则

1. 排版不装点。emoji 不当列表符号、不当小节头、不当句尾装饰，一条消息最多一个，整条没有很正常。判断法：把 emoji 全删，意思掉了一块的那个才许留。
2. 断行要有功能才断。一句一行的诗歌体并回成段；断行只留给列表、代码、引用、对话轮换。
3. 复述只讲对方看不出来的：为什么改、影响什么、下一步做什么。对方眼前的 diff、截图、代码不重念一遍。一行说得清就一行，写不满就短着交。

豁免三条：仓库自带模板从仓库（gitmoji 的 emoji 前缀、Conventional Commits 的格式都是规范，照仓库的来）；用户先用的 emoji 和断行跟着用户；用户明说是营销发布文案时按文案规矩来。
