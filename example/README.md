# example/：初始配置与个人层示范

build/ 是你的私人目录（整目录 gitignore，分发不带），这里放复制起点：

- **combo.json** —— 选层清单，唯一要维护的东西：每个维度选哪个档、装哪些病灶和场景、个人层带哪几份。抄一份到 build/combo.json 按口味改。
- **bans.md** —— 你的判死词表。加词加行，checks/lint.py 自动跟着解析。
- **voice.md** —— 你的语气校准。常用助词、口头禅、颜文字、年代，装了跟人走的档位才生效。
- **personas/** —— 人格卡，一卡一文件。combo.json 写 `"persona": "卡名"` 挂上，单值键，一次只穿一套，写成列表直接编译失败。卡里只放身份（自称、口癖、称呼、姿态、表情库——颜文字和 emoji 用哪些、文章里不随意用），密度修辞这些机制维度不归它管，让位链写在卡的层卡里。

改完 combo.json 跑一句 `python3 tools/bake.py`：自动生成 build/style.md——路由头从各层标题现场拼装，全部选中层的全文合进这一份（机械判罚块剔除）。模型只读这一个文件，Codex 等不认 @ 导入的工具直接贴这份 style.md。换口味永远只是改 combo.json 一个词再重跑，style.md 是生成物，别手改。

编译器顺手执行宪法：同维选两份直接编译失败，文件不存在报错，没选的维度提示"没意见"。

## 为什么规则不住 JSON

规则本体是散文和正反例，JSON 装不下，所以写在 markdown。JSON 只当选层清单（选哪个档），这正是它擅长的。分工：md 是内容，json 是选择，bake 把两者编译成 style.md。
